<Callout type="tip" title="El código es un argumento reproducible">
El principio 2 de Woodward dice que el diseño determina lo estimable. Su
versión computacional: **la herramienta determina lo verificable**. Un
análisis que no se puede re-ejecutar en otro lenguaje es un análisis que
no se puede auditar. Este módulo no enseña sintaxis: enseña a
traducir *estimandos* entre tres ecosistemas y a dejar el proyecto en
estado reproducible.
</Callout>

Este módulo es transversal: conecta las prácticas de los módulos 1–17.
Puede dictarse como orientación inicial o como síntesis final, y cada
tarjeta de herramientas puede revisitarse desde el módulo
correspondiente.

### Tabla 2×2 y medidas de asociación

<LangTabs
  title="La misma tabla en tres interfaces"
  task="Datos del módulo 4 (Pool esquemático): fumadores 166/50 casos de EIC vs. no fumadores 1176/513. Fila 1 = expuestos, columna 1 = casos."
  rCode={`# epiR exige: exposicion en FILAS, desenlace en COLUMNAS,
# y el nivel + primero. table() ordena alfabetico -> invertir.
library(epiR)
tab <- matrix(c(166, 1176, 50, 513), nrow = 2,
              dimnames = list(Fuma = c("Si", "No"),
                              EIC  = c("Si", "No")))
epi.2by2(tab, method = "cohort.count")
# -> cohort.count da RR, OR, RD, PRA con IC95%`}
  sasCode={`data pool;
  input Fuma $ EIC $ n;   /* orden=data preserva categorias */
  datalines;
Si Si 166   Si No 1176
No Si 50    No No 513 ;
proc freq data=pool order=data;
  weight n;
  tables Fuma*EIC / relrisk measures chisq;
  /* RELRISK: OR + "Cohort (Col1 Risk)" = RR de la col. 1 */
run;`}
  pyCode={`import pandas as pd
from statsmodels.stats.contingency_tables import Table2x2

# crosstab ordena alfabetico: forzar el orden con categorias
tab = pd.DataFrame([[166, 1176], [50, 513]],
                   index=["Si", "No"], columns=["Si", "No"])
t = Table2x2(tab.values, shift_zeros=False)
print("OR =", t.oddsratio, t.oddsratio_confint())
print("RR =", t.riskratio, t.riskratio_confint())
# Para medidas epi dedicadas: zepid (RiskRatio, OddsRatio, NNT)`}
  trap={
    <>En R, <code>epi.2by2</code> exige exposición en filas y el desenlace
    positivo en la <em>primera</em> columna; con <code>table()</code> casi
    siempre toca <code>tab[2:1, 2:1]</code>. En SAS, RELRISK reporta el riesgo
    de la <em>columna 1</em> entre fila 1 y fila 2: cambiar el orden cambia
    qué riesgo se reporta (Col1 vs Col2). En pandas, <code>crosstab</code>{' '}
    reordena alfabéticamente y puede voltear la referencia sin aviso.</>
  }
  guide="Ejecuta la pestaña R en una RCell y compara el RR con el reporte 'Cohort (Col1 Risk)' del lado SAS: deben coincidir si las convenciones de tabla coinciden."
/>

### Supervivencia

<LangTabs
  title="Kaplan–Meier, log-rank y Cox en los tres lenguajes"
  task="Curvas de supervivencia por grupo y riesgo proporcional (datos de leucemia, módulo 12)."
  rCode={`library(survival)
s <- Surv(time = t, event = status)
fit <- survfit(s ~ grupo)        # curvas KM
survdiff(s ~ grupo)              # log-rank
coxph(s ~ grupo)                 # Cox: HR + IC`}
  sasCode={`proc lifetest data=leucemia plots=survival;
  time t * status(0);            /* 0 = censurado */
  strata grupo;                  /* curvas + log-rank */
run;
proc phreg data=leucemia;
  model t * status(0) = grupo;   /* Cox */
run;`}
  pyCode={`from lifelines import KaplanMeierFitter, CoxPHFitter
from lifelines.statistics import logrank_test

kmf = KaplanMeierFitter().fit(t, status, label="KM")
logrank_test(t[grupo==1], t[grupo==0],
             status[grupo==1], status[grupo==0])
CoxPHFitter().fit(df, "t", "status").summary  # HR`}
  trap={
    <>La codificación de censura difiere: <code>Surv(t, status)</code> usa
    1 = evento; <code>PHREG</code>/<code>LIFETEST</code> listan los valores
    <em>censurados</em> en <code>model t * status(0)</code> o{' '}
    <code>time t * status(0)</code>; <code>lifelines</code> usa 1 = evento
    como R. Invertir la codificación produce curvas <em>especulares</em> y

### Regresión logística y Poisson

| Tarea | R | SAS | Python |
| --- | --- | --- | --- |
| Logística | `glm(y ~ x, family = binomial)` | `PROC LOGISTIC` | `statsmodels.Logit` |
| <Term k="OR">OR</Term> ajustado | `exp(coef(m))` | salida `OddsRatio` por defecto | `np.exp(res.params)` |
| Hosmer–Lemeshow | `ResourceSelection::hoslem.test()` | `MODEL ... / LACKFIT` | manual / `statsmodels` |
| Poisson / tasas | `glm(y ~ x, family = poisson)` | `PROC GENMOD dist=poisson` | `statsmodels.GLM(family=Poisson())` |
| Logística condicional (matching) | `survival::clogit()` | `PROC LOGISTIC` + `STRATA` | no directo (vía `CoxPHFitter` con estratos) |
| GEE | `geepack::geeglm()` | `PROC GEE` / `PROC GENMOD ... REPEATED` | `statsmodels.GEE` |

<Callout type="warning" title="PROC LOGISTIC modela el logit del nivel que tú no esperas">
Por defecto <code>PROC LOGISTIC</code> modela la probabilidad del nivel
con orden <em>ascendente</em> más bajo: si el desenlace es 0/1, modela
P(Y = 0). Se corrige con <code>MODEL y(event='1') = x</code> o
<code>descending</code>. Un OR invertido (1/OR) es el síntoma clásico.
En R y statsmodels se modela P(Y = 1) por defecto con codificación 0/1.
</Callout>

### Meta-análisis

| Tarea | R | SAS | Python |
| --- | --- | --- | --- |
| Fijo / aleatorios | `metafor::rma()` | `PROC MIXED` con `PARMS` (macro) | `statsmodels` + manual |
| Forest plot | `forest(metafor)` | `ODS GRAPHICS` | `matplotlib` |
| Heterogeneidad | salida de `rma` (Q, I², τ²) | manual | `statsmodels.stats.meta_analysis` |

<Callout type="note" title="La lección de Normand se repite en el software">
Normand (1999) estimó su meta-análisis de efectos aleatorios con REML en
SAS (<code>PROC MIXED</code>); hoy <code>metafor::rma()</code> usa la
fórmula exacta de REML y es la referencia pedagógica. El estimando es el
mismo; lo que cambia es el estimador de τ².
</Callout>

<Callout type="warning" title="El 'epitools' de Python no existe">
En PyPI, <code>epitools</code> es un plugin de napari para análisis de
imagen de tejidos epiteliales; <strong>no</strong> es epidemiología.
<code>epipy</code> (cmrivers) sí tiene tablas 2×2, OR/RR y epicurvas,
pero lleva años sin mantenimiento. Para medidas de asociación en Python
usa <code>statsmodels.stats.contingency_tables.Table2x2</code> o{' '}
<code>zepid</code>.
</Callout>

## Depuración por lenguaje

| Lenguaje | Error típico | Diagnóstico |
| --- | --- | --- |
| R | `object not found` | `ls()`, `traceback()`, ¿falta `library()`? |

## Reproducibilidad y estructura de proyecto


Los principios **FAIR** (Wilkinson et al. 2016, *Sci Data* 3:160018)
aplican al curso: *Findable* (nombres y README claros), *Accessible*
(repo público), *Interoperable* (CSV/Parquet, no .rds/.sas7bdat como
único formato), *Reusable* (licencia + metadatos + `sessionInfo()`).
Tukey ya lo decía en 1962 (*Ann Math Statist* 33:1–67): el análisis de
datos es una ciencia con métodos propios, no un apéndice del teorema.

  code={`# Tabla canonica del curso (módulo 4): Pool, fumar x EIC
tab <- matrix(c(166, 50, 1176, 513), nrow = 2,
              dimnames = list(Fuma = c("Si", "No"),
                              EIC  = c("Si", "No")))
# Convencion Woodward: filas exposicion, cols desenlace, + primero.
# En R local: epiR::epi.2by2(tab, method = "cohort.count") lo hace todo.
# epiR no esta en el repo wasm de WebR -> equivalente en base R:
a <- tab[1,1]; b <- tab[1,2]; c2 <- tab[2,1]; d <- tab[2,2]
r1 <- a/(a+b); r0 <- c2/(c2+d)
RR <- r1/r0; OR <- a*d/(b*c2); RD <- r1 - r0
se_or <- sqrt(1/a + 1/b + 1/c2 + 1/d)
se_rr <- sqrt(1/a - 1/(a+b) + 1/c2 - 1/(c2+d))
cat(sprintf("RR = %.2f  IC95%% [%.2f, %.2f]\\n",
            RR, exp(log(RR)-1.96*se_rr), exp(log(RR)+1.96*se_rr)))
cat(sprintf("OR = %.2f  IC95%% [%.2f, %.2f]\\n",
            OR, exp(log(OR)-1.96*se_or), exp(log(OR)+1.96*se_or)))
cat(sprintf("RD = %.4f\\n", RD))
# mantelhaen.test exige >= 2 estratos; con una tabla el test es Pearson:
chisq.test(tab, correct = FALSE)
# Tu turno: traduce a SAS (PROC FREQ) y Python (Table2x2)
# en papel o SAS OnDemand, y compara los tres OR.`}
