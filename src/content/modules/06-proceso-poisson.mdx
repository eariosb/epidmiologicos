## 1. Contar en el tiempo continuo

Las cadenas de los módulos 2 y 3 avanzaban por pasos: año a año el asegurado
cambiaba de clase, día a día cambiaba el clima. Pero muchos sistemas no tienen
un reloj natural de pasos: las reclamaciones a una aseguradora, las llamadas a
un conmutador, los clientes de una ventanilla llegan en **instantes
impredecibles del tiempo continuo**.

El proceso de conteo más simple y más importante es el de Poisson. Un proceso
$N = \{N(t)\}_{t \geq 0}$ es de **conteo** si $N(t)$ es el número de eventos
ocurridos en $[0, t]$: empieza en cero, es entero y creciente. Lo que lo hace
"de Poisson" son tres exigencias sobre sus incrementos:

1. $N(0) = 0$.
2. **Incrementos independientes**: lo contado en intervalos disjuntos es
   independiente.
3. **Incrementos estacionarios de ley Poisson**: $N(t + s) - N(s) \sim
   \mathrm{Poisson}(\lambda t)$, solo depende de la longitud $t$.

El parámetro $\lambda > 0$ es la **tasa** del proceso: eventos esperados por
unidad de tiempo. De las tres condiciones se deduce el resto del
comportamiento del proceso, y de eso trata este módulo.

<Callout type="tip" title="Por qué Poisson y no otro conteo">

Pedir incrementos independientes y estacionarios con saltos de a uno es pedir
lo mínimo razonable: no hay memoria, no hay estacionalidad, no hay llegadas
múltiples. Es el análogo en tiempo continuo de la caminata aleatoria simple:
el modelo base sobre el que se construyen los procesos con estructura más
rica (compuestos, no homogéneos, marcados) que veremos en el bloque IV.

</Callout>

## 2. Los tiempos entre llegadas son exponenciales

Sea $T_1$ el instante del primer evento. El evento $T_1 > t$ ocurre si y solo
si no hubo llegadas en $[0, t]$, es decir, $N(t) = 0$. Entonces:

$$P(T_1 > t) = P(N(t) = 0) = e^{-\lambda t}$$

y $T_1 \sim \mathrm{Exp}(\lambda)$. El mismo argumento sobre cada intervalo
posterior da el resultado estructural del proceso: **los tiempos entre
llegadas consecutivas $T_1, T_2, \dots$ son independientes e idénticamente
$\mathrm{Exp}(\lambda)$**.

Esta es la segunda caracterización del proceso de Poisson, y la que usaremos
para simular: lanzar exponenciales sucesivas y acumular.

<RCell
  id="06/poisson-interarrivos"
  title="Construir el proceso lanzando exponenciales"
  code={`set.seed(7)
lam <- 2          # dos eventos por unidad de tiempo, en promedio
horizonte <- 10

# Tiempos entre llegadas: acumulamos exponenciales hasta pasar el horizonte
inter <- rexp(60, rate = lam)
llegadas <- cumsum(inter)
llegadas <- llegadas[llegadas <= horizonte]
N_t <- length(llegadas)
cat("Eventos en [0,10]:", N_t, "| esperado:", lam * horizonte, "\\n")

# Trayectoria de conteo
t_grid <- seq(0, horizonte, by = 0.05)
tray <- sapply(t_grid, function(t) sum(llegadas <= t))
plot(t_grid, tray, type = "s", lwd = 2, col = "#5b21b6",
     main = "Una trayectoria del proceso de Poisson (lambda = 2)",
     xlab = "t", ylab = "N(t)")
abline(h = N_t, lty = 3, col = "gray60")`}
/>

La función de conteo es una escalera: constante entre llegadas, con saltos de
tamaño 1 en cada $T_k$. Que los saltos sean unitarios no es un detalle menor:
es lo que distingue al Poisson puro del Poisson **compuesto** del bloque IV,
donde cada evento trae una magnitud aleatoria (la severidad de la
reclamación).

## 3. La exponencial no tiene memoria

La distribución exponencial es la única ley continua con la propiedad de
**pérdida de memoria**:

$$P(T > s + t \mid T > s) = P(T > t) \quad \text{para todo } s, t \geq 0$$

Si ya esperaste $s$ minutos sin que llegue nadie, la espera restante es
exponencial fresca, como si acabaras de llegar a la fila. Esta propiedad es la
razón por la que el proceso de Poisson tiene incrementos independientes, y es
la base del Quiz 2: la probabilidad de esperar 10 minutos más **no depende**
de lo que ya esperaste.

<Callout type="warning" title="La paradoja de la espera">

La pérdida de memoria tiene una consecuencia contraintuitiva que aparece en
el Taller 2: si las buses llegan según un proceso de Poisson y llegas en un
instante cualquiera, el tiempo **desde la bus anterior** y el tiempo **hasta
la próxima** tienen la misma media $1/\lambda$; entre los dos, el intervalo
que te tocó mide en promedio $2/\lambda$, el doble del intervalo típico.
Llegar en un instante fijo sesga hacia intervalos largos: es el sesgo de
muestreo por longitud, no un fallo del modelo.

</Callout>

## 4. Llegadas condicionadas: uniformes y binomiales

Aquí está el resultado más bonito del módulo, y el corazón del Quiz 2.
Supón que sabes que en $[0, t]$ ocurrió **exactamente un** evento: $N(t) = 1$.
¿Dónde ocurrió? Para $s < t$:

$$P(T_1 \leq s \mid N(t) = 1) = \frac{P(N(s) = 1, N(t) - N(s) = 0)}{P(N(t) = 1)} = \frac{s}{t}$$

La llegada es **uniforme en $[0, t]$**. La intuición: como el proceso no
tiene memoria ni preferencias temporales, "un evento en $[0,t]$" no le dice
nada al tiempo donde cayó.

El resultado se generaliza: condicionadas a $N(t) = n$, las $n$ llegadas se
distribuyen como los **estadísticos de orden de $n$ uniformes**
independientes en $[0, t]$. Y el conteo en una subventana es binomial:

$$P(N(s) = k \mid N(t) = n) = \binom{n}{k} \left(\frac{s}{t}\right)^k \left(1 - \frac{s}{t}\right)^{n-k}$$

<RCell
  id="06/poisson-condicional"
  title="Verificación Monte Carlo de la estructura condicional"
  code={`set.seed(11)
lam <- 2; t_fijo <- 5
reps <- 4000

# Condicionamos a N(t_fijo) = 1 y miramos donde cayo la llegada
t1_cond <- replicate(reps, {
  t <- 0
  repeat {
    t <- t + rexp(1, lam)
    if (t > t_fijo) return(NA)          # la 1ra llegada ya se paso
    t2 <- t + rexp(1, lam)
    if (t2 > t_fijo) return(t)          # exactamente 1 llegada en [0, t_fijo]
    t <- t2
  }
})
t1_cond <- t1_cond[!is.na(t1_cond)]
cat("n =", length(t1_cond), "casos con N(5) = 1\\n")
cat("media empirica:", sprintf("%.3f", mean(t1_cond)),
    "| uniforme esperada:", sprintf("%.3f", t_fijo / 2), "\\n")

# Estructura binomial: de los procesos con N(5) = 3, cuantos cayeron en [0, 2]
primeras <- replicate(reps, {
  tt <- cumsum(rexp(4, lam))
  if (tt[4] <= t_fijo) return(NA)
  sum(tt[1:3] <= 2)
})
primeras <- primeras[!is.na(primeras)]
cat("P(N(2)=k | N(5)=3) empirico:",
    sprintf("%.3f", mean(primeras == 2)),
    "| binomial teorico:",
    sprintf("%.3f", dbinom(2, 3, 2 / 5)), "\\n")`}
/>

La condicional uniforme es también una herramienta de simulación: para
generar las llegadas de un Poisson condicionado a $n$ eventos, basta lanzar
$n$ uniformes y ordenarlas.

## 5. Adelgazamiento y superposición

Dos operaciones cierran el kit del módulo, y ambas aparecen en el Quiz 2.

**Adelgazamiento (thinning).** Si cada evento de un Poisson($\lambda$) se
clasifica de tipo $i$ con probabilidad $p_i$ de forma independiente, los
procesos por tipo son Poisson **independientes** de tasas $\lambda p_i$. La
independencia es lo sorprendente: ver una llegada de tipo A no dice nada
sobre la siguiente de tipo B.

**Superposición.** Sumar procesos de Poisson independientes da un proceso de
Poisson con la suma de tasas. Las dos operaciones son inversas: adelgazar
divide el flujo, superponer lo fusiona.

<RCell
  id="06/poisson-thinning"
  title="Adelgazamiento: reclamaciones por severidad"
  code={`set.seed(19)
lam <- 5        # reclamaciones por semana
p_alta <- 0.2   # fraccion de reclamaciones graves
horizonte <- 52

inter <- rexp(400, lam)
lleg <- cumsum(inter); lleg <- lleg[lleg <= horizonte]
tipo <- rbinom(length(lleg), 1, p_alta)   # 1 = grave
graves <- lleg[tipo == 1]

cat("Total:", length(lleg), "| graves:", length(graves),
    "| esperadas:", sprintf("%.1f", lam * p_alta * horizonte), "\\n")

# Los tiempos entre eventos graves deberian ser Exp(lam * p_alta) = Exp(1)
inter_graves <- diff(graves)
cat("Media entre graves:", sprintf("%.2f", mean(inter_graves)),
    "| teorica:", sprintf("%.2f", 1 / (lam * p_alta)), "\\n")

hist(inter_graves, breaks = 15, col = "#c4b5fd", border = "white",
     main = "Interarrivos del subproceso de reclamaciones graves",
     xlab = "semanas entre reclamaciones graves", freq = FALSE)
curve(dexp(x, rate = lam * p_alta), add = TRUE, col = "#5b21b6", lwd = 2)`}
/>

## 6. La covarianza de los conteos

Para cerrar el módulo, una cuenta del Taller 2 que vuelve a aparecer cuando
estudiemos procesos de segundo orden. Como $N(s)$ y $N(t) - N(s)$ son
independientes para $s < t$:

$$\mathrm{Cov}(N(s), N(t)) = \mathrm{Cov}(N(s), N(s) + N(t) - N(s)) = \mathrm{Var}(N(s)) = \lambda s$$

y en general $\mathrm{Cov}(N(s), N(t)) = \lambda \min(s, t)$. Es la misma
función de autocovarianza que tendrá el proceso de Wiener en el bloque III,
y no es casualidad: la estructura de incrementos independientes la produce.

sim_llegadas <- function(h) {
  tt <- cumsum(rexp(2000, lam))
  tt[tt <= h]
}

# ---- 1. Semanas sin eventos ----
lleg <- sim_llegadas(semanas)
semana_de <- ceiling(lleg)                 # en que semana cayo cada evento
semanas_vacias <- sum(!(1:semanas %in% semana_de))

t1 <- t1[!is.na(t1)]

cat("Cov empirica:", sprintf("%.2f", cov(N2, N5)),
    "| teorica:", sprintf("%.2f", lam * 2), "\\n")

# ---- 4. Independencia del adelgazamiento ----
reps <- 2000
c1 <- c2 <- numeric(reps)
for (i in 1:reps) {
  tt <- sim_llegadas(1)                    # una semana

  c1[i] <- sum(tipo == 1); c2[i] <- sum(tipo == 0)
