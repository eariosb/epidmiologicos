<Callout type="tip" title="El pareamiento mueve la confusión al diseño; el precio se paga en el análisis">
El <Term k="pareamiento">pareamiento</Term> (matching) controla el
confusor **en el diseño**: cada caso se empareja con un control del mismo
nivel del confusor (edad, sexo, vecindario). Cambia la unidad de análisis:
ya no son sujetos sino **parejas**, y solo las parejas discordantes
aportan evidencia.
</Callout>

## La tabla de parejas y McNemar

$$
\begin{array}{c|cc}
 & \text{control } E+ & \text{control } E- \\\hline
\text{caso } E+ & a & b\\
\text{caso } E- & c & d
\end{array}
\qquad
\chi^2_{McN} = \frac{(b-c)^2}{b+c},\quad
\widehat{OR} = \frac{b}{c}
$$

<Callout type="warning" title="Solo los discordantes aportan evidencia">
Las parejas concordantes (ambos expuestos o ambos no) no aportan nada al
contrastar la exposición: <Term k="McNemar">McNemar</Term> usa solo $b$ y
$c$. Un estudio pareado con 500 parejas pero $b+c=6$ tiene menos evidencia
que uno con $b+c=40$.
</Callout>

El explorador muestra cada pareja como un icono: caso a la izquierda,
control a la derecha, relleno si estaba expuesto. Solo las parejas
discordantes, en color, entran a la prueba.

## La equivalencia McNemar ⇔ CMH

En pareamiento 1:1 cada pareja es un estrato de tamaño 2, y la estadística
de <Term k="CMH">Cochran–Mantel–Haenszel</Term> colapsa exactamente al χ²
de McNemar. No es aproximación: es la misma prueba. El código siguiente
la verifica con las parejas de caso_control_11.csv.

  title="caso_control_11.csv: parejas caso-control 1:1"
  description="50 parejas; cada fila es una pareja con la exposición del caso y la de su control pareado."
  source="Material de clase, clase 22 (Salazar)"
  variables={[
    { name: 'caso', type: 'binario', description: '1 = caso expuesto, 0 = no expuesto' },
    { name: 'control', type: 'binario', description: '1 = control expuesto, 0 = no expuesto' },
  ]}
/>

<RCell
  id="15/mcnemar-cmh"
  title="McNemar = CMH en parejas 1:1 reales"
  code={`# caso_control_11.csv: 50 parejas, exposicion de cada miembro.
cc <- read.csv("caso_control_11.csv")
print(head(cc))

# Tabla de parejas: exposicion del caso x exposicion del control.
tab <- table(cc$caso, cc$control)
print(tab)

b <- tab["1","0"]; c0 <- tab["0","1"]
cat(sprintf("discordantes: b = %d, c = %d  ->  OR = b/c = %.3f\\n",
            b, c0, b/c0))

# Prueba 1: McNemar directo, y su version exacta (binomial sobre b+c).
print(mcnemar.test(tab, correct = FALSE))
ic <- binom.test(b, b + c0)$conf.int
cat(sprintf("McNemar exacto: p = %.3f | OR = %.2f, IC95%% exacto %.2f-%.2f\\n",
            binom.test(b, b + c0)$p.value, b/c0, ic[1]/(1-ic[1]), ic[2]/(1-ic[2])))

# Prueba 2: CMH sobre el array de estratos (un estrato por pareja).
# Cada estrato es la tabla 2x2 de la pareja: filas = miembro
# (caso/control), columnas = exposicion; cada pareja aporta n = 2.
n <- nrow(cc)
arr <- array(0, dim = c(2,2,n),
             dimnames = list(miembro = c("caso","control"),
                             expo = c("E+","E-"), par = NULL))
for (i in 1:n) {
  arr[1, 2 - cc$caso[i], i]    <- 1   # fila caso: expuesto -> columna "E+"
  arr[2, 2 - cc$control[i], i] <- 1   # fila control
}
print(mantelhaen.test(arr, correct = FALSE))
cat("\\nChi2 McNemar = Chi2 CMH, y OR de MH = b/c: la equivalencia de la clase 22.\\n")`}
/>

<SasBlock code={`proc import datafile="caso_control_11.csv" out=cc dbms=csv replace;
  getnames=yes;
run;
/* Cada fila YA es una pareja: caso x control */
proc freq data=cc;
  tables caso*control / agree;   /* McNemar asintotico bajo AGREE */
  exact mcnem;                    /* McNemar exacto */
run;
/* PROC FREQ no imprime el OR pareado: OR = b/c con b = (caso 1,
   control 0) y c = (caso 0, control 1), leidos de la tabla */
/* La equivalencia con CMH: cada pareja es un estrato.
   En formato largo (una fila por miembro con ID de pareja):
   tables ID*miembro*exposicion / cmh  da el mismo chi2 */`} />

Las dos pruebas dan χ² = 6.26 y el estimador de Mantel–Haenszel
reproduce b/c = 20/7 = 2.86. Con 27 parejas discordantes el IC exacto
va de 1.16 a 8.0: hay asociación, pero su tamaño queda poco definido.
Las 23 parejas concordantes no cambian nada de esto.

## La regresión logística condicional

El dataset <Term k="DDIMER">DDIMER</Term> (embolia pulmonar y dímero D)
tiene sets de tamaño variable, algunos con más de un caso; y bcg_matching.csv (vacuna <Term k="BCG">BCG</Term> y
meningitis, Rodrigues 1991) pareó **1 caso con 5 controles** en cada uno
de 111 sets. El McNemar ya no alcanza: el análisis correcto es la
**regresión logística condicional** (<Term k="clogit">clogit</Term>), que
estima el OR dentro de cada estrato de matching sin estimar los efectos
del estrato:

<RCell
  id="15/ddimer-clogit"
  title="Matching variable con clogit (DDIMER)"
  code={`# ddimer.csv: setno = estrato de matching, cc = caso(1)/control(0),
# ddimer = exposicion, SBP = presion sistolica.
dd <- read.csv("ddimer.csv")
print(head(dd)); print(table(dd$setno))

# Logistica condicional: un coeficiente por covariable, estrato por setno.
library(survival)
fit <- clogit(cc ~ ddimer + SBP + strata(setno), data = dd)
print(summary(fit))

# El OR de ddimer ajustado por SBP dentro de cada set:
cat("\\nOR(ddimer) =", round(exp(coef(fit)["ddimer"]), 3), "\\n")

# bcg_matching.csv tambien es 1:c: 111 sets con 1 caso + 5 controles.
bcg <- read.csv("bcg_matching.csv")
bcg$case <- as.integer(bcg$Case_control == "Case")
fit_b <- clogit(case ~ Bcg_Status + strata(ID), data = bcg)
ic_b <- exp(confint(fit_b))
cat("OR(BCG pareado) =", round(exp(coef(fit_b)), 3),
    " IC95%", round(ic_b, 2), "\\n")

# Si se ignorara el matching (tabla 2x2 pooled) el OR sale distinto:
t <- table(bcg$Bcg_Status, bcg$case)
cat("OR ingenuo (sin parear) =",
    round(t[2,2]*t[1,1]/(t[2,1]*t[1,2]), 3), "\\n")`}
/>

<SasBlock code={`proc import datafile="ddimer.csv" out=dd dbms=csv replace;
  getnames=yes;
run;
/* clogit -> PROC LOGISTIC con STRATA (logistica condicional):
   elimina los interceptos por setno, estima solo los betas */
proc logistic data=dd;
  strata setno;
  model cc(event='1') = ddimer SBP;
run;
/* Alternativa equivalente: PROC PHREG con ties=discrete
   (la logistica condicional es un Cox estratificado con un
   tiempo ficticio: los casos "fallan" antes que sus controles) */
data dd2; set dd; t = 2 - cc; run;
proc phreg data=dd2;
  model t*cc(0) = ddimer SBP / ties=discrete;
  strata setno;
run;`} />

La salida dice `coxph(... method = "exact")`: la logística condicional
es un Cox estratificado con un tiempo ficticio. En DDIMER, el OR del
dímero D ajustado por presión es 1.21 con IC 0.50–2.94, así que estos 28
casos no permiten afirmar ni descartar un efecto; la presión sistólica
sí se asocia (OR 1.022 por mmHg, ≈ 1.24 por cada 10 mmHg). En BCG, el
OR pareado es 0.52 (IC 0.30–0.90) y el ingenuo 0.69.

<Callout type="note" title="Por qué logística condicional y no ordinaria">
El matching introduce un intercepto por estrato: tantos parámetros como
parejas. La verosimilitud condicional los elimina condicionando en el
número de casos por estrato: solo se estiman los <Term k="β-coef">β</Term> de las covariables,
que es lo que interesa.
</Callout>

## Conducir el estudio: el diseño pareado

El pareamiento es el único recurso que **convierte el análisis en el
diseño**: la confusión se controla antes de recoger datos, a costa de
información. Sus siete pasos:

<ConductStudy design="estudio pareado">
  <ConductStep n={1}>
    Mismo objetivo que el caso-control no pareado: el OR. Se recurre al
    pareamiento cuando un confusor fuerte y categórico (edad, sexo,
    hospital) haría difícil ajustarlo después, o cuando los controles
    elegibles son escasos.
  </ConductStep>
  <ConductStep n={2}>
    Idéntica regla que sin pareamiento: los controles salen de la misma
    población fuente que produjo los casos.
  </ConductStep>
  <ConductStep n={3}>
    Por cada caso, c controles del mismo nivel del confusor. La
    proporción fija (1:1, 1:5) es una decisión de eficiencia: cerca del
    nulo, la eficiencia relativa a infinitos controles es c/(c+1), es
    decir 50 % con 1, 80 % con 4 y 83 % con 5, así que pasar de 4 a más
    aporta poco. La proporción variable es lo que ocurre cuando el pool
    no alcanza.
  </ConductStep>
  <ConductStep n={4}>
    La variable de pareamiento debe medirse sin error y **no ser la
    exposición ni un mediador**: parear por un factor de interés lo
    congela dentro de cada set.
  </ConductStep>
  <ConductStep n={5}>
    La unidad ya no es el individuo: es la pareja o el conjunto. El
    archivo debe llevar la etiqueta del set en cada fila — sin ella el
    análisis condicional es imposible y el pareamiento quedó en
    vano.
  </ConductStep>
  <ConductStep n={6}>
    Auditar la estructura: ¿cuántos miembros por set? ¿Cuántos sets
    discriminan exposición? Un set concordante (caso y controles todos
    expuestos o todos no) no aporta a la condicional.
  </ConductStep>
  <ConductStep n={7}>
    <strong>Obligatorio: análisis condicional.</strong> McNemar en 1:1,
    clogit en 1:c. El OR de la tabla sin estratificar ignora el
    pareamiento y, cuando el factor de pareamiento se asocia con la
    exposición, suele sesgar hacia el nulo (BCG: 0.69 frente a 0.52).
    El diseño que controla la confusión exige el análisis que la
    respeta.
  </ConductStep>
</ConductStudy>

### Ejercicio de conducción: sets que no respetan el plan

DDIMER tenía un plan 1:c y la realidad lo incumplió — los sets tienen
tamaño variable. El archivo lo dice si lo miras:

<RCell
  id="15/ddimer-sets"
  title="¿Todos los sets son 1:c con el mismo c?"
  code={`# setno = estrato de matching, cc = caso(1)/control(0)
dd <- read.csv("ddimer.csv")
miembros <- table(dd$setno)
cat("sets:", length(miembros), "\\n")
cat("miembros por set:\\n")
print(table(miembros))

# Cuantos casos por set? (DDIMER no es estrictamente 1:c)
casos <- tapply(dd$cc, dd$setno, sum)
cat("\\ncasos por set:\\n")
print(table(casos))
cat("sets con mas de un caso:", sum(casos > 1), "\\n")

# La verosimilitud condicional no exige c fijo:
cat("\\npor eso clogit maneja sets de tamano variable\\n")`}
/>

La lección de conducción: el archivo manda sobre el protocolo. DDIMER
no es 1:c con c fijo (hay sets con 1, 2 y 3 casos), y eso no lo
invalida: la verosimilitud condicional se escribe por set y tolera
tamaños variables. Lo que sí exige es verificar la estructura antes de
analizarla: quien asume 1:5 fijo y cruza filas por posición, rompe los
sets.

## Los límites del matching

El pareamiento no es gratis y sus fracasos tienen nombre:

- **Overmatching**: si se parean por una variable que no es confusora —
  por ejemplo un mero correlato de la exposición — se fabrican
  concordancias artificiales: bajo análisis condicional el <Term k="OR">OR</Term> no se
  sesga, pero la eficiencia cae porque sobran parejas que no discriminan.
  El sesgo sí aparece cuando se parean por un mediador causal (se
  bloquea parte del efecto E → D). Regla práctica: solo se parean por
  confusores verdaderos (el <Term k="DAG">DAG</Term> del módulo 7 decide), nunca por lo
  que el investigador tenga a la mano.
- **Conjuntos incompletos vs. concordantes**: son dos cosas distintas.
  Un set *incompleto* —un caso con menos controles de los planeados, o
  controles sin su caso— sí aporta a la verosimilitud condicional
  mientras conserve contraste de exposición. Lo que no aporta es el set
  *concordante o no informativo*: caso y controles todos expuestos (o
  todos no expuestos), o un set donde la exposición del caso no difiere
  de la de sus controles. No es un bug: la condicional solo usa los
  sets que discriminan. En DDIMER, sets con c ≠ 1 son exactamente donde
  esta disciplina importa.
- **Legionella**: el ejemplo de las clases 21–23 es la lección de costo.
  La investigación del brote de legionelosis muestra la tensión clásica:
  criterios de pareamiento muy específicos reducen el pool de controles
  elegibles y dejan sets sin contraste de exposición utilizable. El
  diseño gana control de confusión y pierde eficiencia: el precio del
  matching se paga en sets que no informan.

<Callout type="warning" title="Cuándo NO parear">
No parear por: (a) variables en el camino causal E → D (mediadores),
(b) meros correlatos de la exposición sin vínculo con el desenlace,
(c) factores que son ellos mismos de interés. Parear por un factor
interesante lo congela: jamás podrás estimar su efecto porque dentro de
cada pareja no varía.
</Callout>
