<Callout type="tip" title="El pareamiento mueve la confusión al diseño; el precio se paga en el análisis">
El <Term k="pareamiento">pareamiento</Term> (matching) controla el
confusor **en el diseño**: cada caso se empareja con un control del mismo
nivel del confusor (edad, sexo, vecindario). Cambia la unidad de análisis:
ya no son sujetos sino **parejas**, y solo las parejas discordantes
aportan evidencia.
</Callout>

## La tabla de parejas y McNemar

$$
\begin{array}{c|cc}
 & \text{control } E+ & \text{control } E- \\\hline
\text{caso } E+ & a & b\\
\text{caso } E- & c & d
\end{array}
\qquad
\chi^2_{McN} = \frac{(b-c)^2}{b+c},\quad
\widehat{OR} = \frac{b}{c}
$$

<Callout type="warning" title="Solo los discordantes aportan evidencia">
Las parejas concordantes (ambos expuestos o ambos no) no aportan nada al
contrastar la exposición: <Term k="McNemar">McNemar</Term> usa solo $b$ y
$c$. Un estudio pareado con 500 parejas pero $b+c=6$ tiene menos evidencia
que uno con $b+c=40$.
</Callout>

## La equivalencia McNemar ⇔ CMH

En pareamiento 1:1 cada pareja es un estrato de tamaño 2, y la estadística
de <Term k="CMH">Cochran–Mantel–Haenszel</Term> colapsa exactamente al χ²
de McNemar. No es aproximación: es la misma prueba. El código siguiente
la verifica con las parejas de caso_control_11.csv.

<DataTable
  title="caso_control_11.csv: parejas caso-control 1:1"
  description="50 parejas; cada fila es una pareja con la exposición del caso y la de su control pareado."
  source="Material de clase, clase 22 (Salazar)"
  variables={[
    { name: 'caso', type: 'binario', description: '1 = caso expuesto, 0 = no expuesto' },
    { name: 'control', type: 'binario', description: '1 = control expuesto, 0 = no expuesto' },
  ]}
/>

<RCell
  id="15/mcnemar-cmh"
  title="McNemar = CMH en parejas 1:1 reales"
  code={`# caso_control_11.csv: 50 parejas, exposicion de cada miembro.
cc <- read.csv("caso_control_11.csv")
print(head(cc))

# Tabla de parejas: exposicion del caso x exposicion del control.
tab <- table(cc$caso, cc$control)
print(tab)

b <- tab["1","0"]; c0 <- tab["0","1"]
cat(sprintf("discordantes: b = %d, c = %d  ->  OR = b/c = %.3f\\n",
            b, c0, b/c0))

# Prueba 1: McNemar directo.
print(mcnemar.test(tab, correct = FALSE))

# Prueba 2: CMH sobre el array de estratos (un estrato por pareja).
# Cada estrato es la tabla 2x2 de la pareja: filas = miembro
# (caso/control), columnas = exposicion; cada pareja aporta n = 2.
n <- nrow(cc)
arr <- array(0, dim = c(2,2,n),
             dimnames = list(miembro = c("caso","control"),
                             expo = c("E+","E-"), par = NULL))
for (i in 1:n) {
  arr[1, cc$caso[i] + 1, i]    <- 1   # fila caso
  arr[2, cc$control[i] + 1, i] <- 1   # fila control
}
print(mantelhaen.test(arr, correct = FALSE))
cat("\\nChi2 McNemar = Chi2 CMH: la equivalencia de la clase 22.\\n")`}
/>

<SasBlock code={`proc import datafile="caso_control_11.csv" out=cc dbms=csv replace;
  getnames=yes;
run;
/* Cada fila YA es una pareja: caso x control */
proc freq data=cc;
  tables caso*control / agree;   /* McNemar bajo AGREE */
  exact mcnem;                    /* McNemar exacto + OR = b/c */
run;
/* La equivalencia con CMH: cada pareja es un estrato.
   En formato largo (una fila por miembro con ID de pareja):
   tables ID*miembro*exposicion / cmh  da el mismo chi2 */`} />

## La regresión logística condicional

El dataset <Term k="DDIMER">DDIMER</Term> (embolia pulmonar y dímero D)
parea sets 1:c con c variable — y bcg_matching.csv (vacuna <Term k="BCG">BCG</Term> y
meningitis, Rodrigues 1991) pareó **1 caso con 5 controles** en cada uno
de 111 sets. El McNemar ya no alcanza: el análisis correcto es la
**regresión logística condicional** (<Term k="clogit">clogit</Term>), que
estima el OR dentro de cada estrato de matching sin estimar los efectos
del estrato:

<RCell
  id="15/ddimer-clogit"
  title="Matching variable con clogit (DDIMER)"
  code={`# ddimer.csv: setno = estrato de matching, cc = caso(1)/control(0),
# ddimer = exposicion, SBP = presion sistolica.
dd <- read.csv("ddimer.csv")
print(head(dd)); print(table(dd$setno))

# Logistica condicional: un coeficiente por covariable, estrato por setno.
library(survival)
fit <- clogit(cc ~ ddimer + SBP + strata(setno), data = dd)
print(summary(fit))

# El OR de ddimer ajustado por SBP dentro de cada set:
cat("\\nOR(ddimer) =", round(exp(coef(fit)["ddimer"]), 3))

# bcg_matching.csv tambien es 1:c: 111 sets con 1 caso + 5 controles.
bcg <- read.csv("bcg_matching.csv")
bcg$case <- as.integer(bcg$Case_control == "Case")
fit_b <- clogit(case ~ Bcg_Status + strata(ID), data = bcg)
cat("OR(BCG pareado) =", round(exp(coef(fit_b)), 3))

# Si se ignorara el matching (tabla 2x2 pooled) el OR sale distinto:
t <- table(bcg$Bcg_Status, bcg$case)
cat("OR ingenuo (sin parear) =",
    round(t[2,2]*t[1,1]/(t[2,1]*t[1,2]), 3))`}
/>

<SasBlock code={`proc import datafile="ddimer.csv" out=dd dbms=csv replace;
  getnames=yes;
run;
/* clogit -> PROC LOGISTIC con STRATA (logistica condicional):
   elimina los interceptos por setno, estima solo los betas */
proc logistic data=dd;
  strata setno;
  model cc(event='1') = ddimer SBP;
run;
/* Alternativa equivalente: PROC PHREG con ties=discrete
   (la logistica condicional es un Cox estratificado) */
proc phreg data=dd;
  model cc = ddimer SBP / ties=discrete;
  strata setno;
run;`} />

<Callout type="note" title="Por qué logística condicional y no ordinaria">
El matching introduce un intercepto por estrato: tantos parámetros como
parejas. La verosimilitud condicional los elimina condicionando en el
número de casos por estrato: solo se estiman los β de las covariables,
que es lo que interesa.
</Callout>

## Los límites del matching

El pareamiento no es gratis y sus fracasos tienen nombre:

- **Overmatching**: si se parean por una variable que no es confusora —
  por ejemplo un mediador causal o un correlato de la exposición — se
  fabrican concordancias artificiales y el <Term k="OR">OR</Term> pareado se sesga hacia 1.
  Regla práctica: solo se parean por confusores verdaderos (el <Term k="DAG">DAG</Term> del
  módulo 7 decide), nunca por lo que el investigador tenga a la mano.
- **Conjuntos incompletos**: en clogit con 1:c variable, un set cuyo
  caso tiene exposición que no añade contraste sobre los controles
  disponibles (o al revés) no contribuye a la verosimilitud. No es un
  bug: la condicional solo usa los sets que discriminan. En DDIMER,
  sets con c ≠ 1 son exactamente donde esta disciplina importa.
- **Legionella**: el ejemplo de las clases 21–23 es la lección de costo.
  En la investigación del brote de Filadelfia de 1976, parear casos por
  características tan específicas (asistentes a la convención, rango de
  edad, lugar de alojamiento) dejó pocos controles elegibles y varias
  parejas con exposición discordante inservible. El diseño ganó
  control de confusión y perdió eficiencia: el precio del matching se
  paga en sets que no informan.

<Callout type="warning" title="Cuándo NO parear">
No parear por: (a) variables en el camino causal E → D (mediadores),
(b) meros correlatos de la exposición sin vínculo con el desenlace,
(c) factores que son ellos mismos de interés. Parear por un factor
interesante lo congela: jamás podrás estimar su efecto porque dentro de
cada pareja no varía.
</Callout>
